## 3. 삭제 후보는 0건이다 — 계측기가 "돌았나"가 아니라 "일했나"를 잰다

DESIGN.md §1은 **갈래 (A)이면서 0건인 훅만 삭제 후보**라고 못박는다. 0건이 나온 셋을
소스에서 확인한 결과 **셋 다 (A)가 아니라 (C)다.** `hooklog.fire()`가 전부 조기
반환 뒤, *훅이 실제로 무언가를 바꾼 지점*에 놓여 있기 때문이다.

| 훅 | fire 위치 | 0건의 뜻 |
|:---|:---|:---|
| `session-title-3words.py` | `main():86` — `session_title`이 있고 reshape 결과가 원본과 **다를 때만** (`:79`·`:83` 조기 return) | 제목을 실제로 고쳐 쓴 적이 0회 |
| `fix_surrogate.py` | `main():166` — `if found_any` | **깨진 서로게이트를 한 번도 안 만났다** = 정상 동작 |
| `graph-offer.sh` | `:143` — 제안을 emit한 뒤. 그래프·마커가 있으면 `:73`·`:75`·`:101`에서 조기 `exit 0` | 두 저장소 다 이미 그래프가 있어 제안할 게 없었다 |

셋 다 **훅은 매 세션 돌았고, 할 일이 없어서 로그를 안 남겼다.** 이걸 미발화로 읽고
지우면 "서로게이트 깨짐이 없었으니 서로게이트 수리기를 지운다"가 된다.

**그래서 Task 4의 전제 — "발화 0 = 삭제 후보" — 는 이 배선에서 성립하지 않는다.**
계측이 (B)를 (A)로 전환할 것이라던 DESIGN.md §1의 기대(라인 234)도 12개 중 3개에
대해서는 빗나갔다: (B)에서 (C)로 갔을 뿐이다.

**조치 완료 (같은 날)**: 셋 다 `acted` 필드를 남기도록 고쳤다 — 이제 "돌았지만 할 일
없었다"와 "아예 안 돌았다"가 갈린다.

- `hooklog.fire()`는 원래부터 임의 kwargs를 기록한다(`hooklog.py:36` `row.update(fields)`). 그래서 py 훅 둘은 **스키마가 아니라 호출 위치만** 문제였다 — 조기 반환 뒤로 옮기고 `acted=`를 붙였다. `fix_surrogate`는 트랜스크립트 부재 경로(`:143`)도 `reason="no-transcript"`로 기록한다.
- `graph-offer.sh`는 `printf`가 `{"ts","hook"}` 고정이라 진짜 스키마 문제였다. 조기 `exit 0`이 6곳이라 호출 위치 이동으로는 못 덮어서 **EXIT 트랩**으로 바꿨다. 트랩이 `$?`를 붙잡았다 되돌려준다 — 원본 주석이 경고하던 "마지막 명령이 종료 코드를 덮어쓴다"가 트랩에서도 그대로 성립하기 때문이다.
- 계측기가 없던 `compact-guard.py`도 같은 규약으로 배선했다(`compact_guard.jsonl`, `mode`+`acted`).

검증: `pytest tests/hooks/` **237 passed (exit 0)**, `bash -n` 통과, 격리 디렉터리 스모크에서
네 훅 모두 발화 — `graph-offer`가 조기 exit 경로에서 `acted:false`를 남기는 것까지 확인했다.

**다음 판정은 이 로그가 쌓인 뒤에 한다.** `acted=true`가 계속 0이면 그때는 (A)+0건이고
삭제 근거가 된다. 지금 지우면 안 되는 이유가 사라진 게 아니라, 확인할 수단이 생긴 것이다.
