# MCP Code-Intelligence Tools: python_repl, LSP Suite, ast-grep, deepinit_manifest, Skills Tools

OMC ships a single stdio MCP server named `t` (declared in `.mcp.json` as `node ${CLAUDE_PLUGIN_ROOT}/bridge/mcp-server.cjs`), so every tool surfaces to Claude Code as `mcp__t__<name>` (in plugin installs: `mcp__plugin_oh-my-claudecode_t__<name>`). The bundle is built by esbuild from `src/mcp/standalone-server.ts` (scripts/build-mcp-server.mjs:36), which delegates its tool table to `src/mcp/tool-registry.ts` — the single source of truth for the standalone surface. This section covers the code-intelligence remainder of `src/tools/`: the 12 `lsp_*` tools backed by a pooled JSON-RPC LSP client with devcontainer awareness, the 2 `ast_grep_*` tools over `@ast-grep/napi`, the persistent `python_repl` backed by a per-session Python "gyoshu bridge" process, `deepinit_manifest` (incremental /deepinit change detection), and the 3 skills-listing tools. State/memory/notepad/wiki/trace tools live in the same registry but are another analyst's territory.

## Registration and wiring

Two aggregation paths exist; only the first is what the plugin actually runs:

| Path | File | Consumers | Tool set / order |
|---|---|---|---|
| Standalone stdio server (ACTIVE, plugin) | `src/mcp/tool-registry.ts:52-64` → `src/mcp/standalone-server.ts` | `.mcp.json` → `bridge/mcp-server.cjs` | lsp(12), ast(2), python(1), state, notepad, memory, trace, shared-memory, deepinit(1), wiki, skills(3) |
| In-process SDK server (ACTIVE for Agent SDK embeds) | `src/mcp/omc-tools-server.ts:42-55` (`createSdkMcpServer`, name `"t"`) | `src/index.ts:361` (`mcpServers: { 't': omcToolsServer }`) | same families in a slightly different order (skills before state) **plus** `interop` tools appended when `OMC_INTEROP_TOOLS_ENABLED === '1'` (omc-tools-server.ts:37) |
| `src/tools/index.ts` (`allCustomTools`, `getToolsByCategory`) | src/tools/index.ts:30-48 | none outside tests | VESTIGIAL third aggregation (lsp+ast+python only), with its own duplicate zod→JSON-schema converter |

Every tool is a `ToolDefinition` — `{ name, description, category?, annotations?, schema: ZodRawShape, handler }` (src/tools/types.ts:37-44). The registry converts Zod shapes to JSON Schema by hand (`zodToJsonSchema`, tool-registry.ts:125-147; handles Optional/Default/String/Number-int/Boolean/Array/Enum/Object/Record, falls back to `"string"`). MCP `annotations` (`readOnlyHint`/`destructiveHint`/`idempotentHint`/`openWorldHint`, types.ts:26-35) are emitted only when present; none of the lsp/ast/python/deepinit/skills tools set them.

**Kill switch**: `OMC_DISABLE_TOOLS` (comma-separated, case-insensitive, unknown names silently ignored) filters whole categories at server startup via `parseDisabledGroups` (src/mcp/disable-tools.ts:41-55). Aliases: `python-repl`→python, `deepinit-manifest`→deepinit, `project-memory`→memory (disable-tools.ts:7-26). Categories come from `TOOL_CATEGORIES` in src/constants/names.ts.

**Shutdown**: the standalone server registers signal/stdin/parent-poll handlers (`registerStandaloneShutdownHandlers`) and on shutdown runs `cleanupOwnedBridgeSessions()` (kill Python bridges spawned by this process) then `disconnectAllLsp()`, with a 5 s `setTimeout(() => process.exit(1))` hard deadline (standalone-server.ts:82-109). Rationale documented inline: orphaned jdtls survived server exit (#768).

**Registration trap (latent bug)**: `python-repl/index.ts` exports `pythonReplTool` whose handler returns a raw `string` and whose `schema` is a full `ZodObject`; `python-repl/tool.ts` exports the wrapped `{ content: [...] }` version with `schema: pythonReplSchema.shape`. tool-registry.ts:18-21 carries an all-caps warning "Import from tool.js, NOT index.js!" — yet `omc-tools-server.ts:12` imports from `index.js`, so the in-process SDK path registers the raw-string variant.

## python_repl — persistent Python REPL

One tool, four actions: `execute | interrupt | reset | get_state` (schema src/tools/python-repl/tool.ts:49-94). Namespacing key is `researchSessionID` (required, min 1 char): each distinct ID gets its own long-lived Python process ("bridge"), lock, and socket. Other inputs: `code` (required for execute), `executionLabel`, `executionTimeout` (default `300000` ms), `queueTimeout` (default `30000` ms, this is the *lock acquisition* timeout), `projectDir` (venv discovery root, default cwd).

```
handler (tool.ts:521)                          per researchSessionID
  1 zod validate ──► 2 validatePathSegment(sessionID)      runtimeDir/{sha256(id)[:12]}/
  3 execute requires code                                    ├─ session.lock      (O_EXCL JSON)
  4 SessionLock.acquire(queueTimeout)                        ├─ bridge_meta.json  (BridgeMeta)
  5 ensureBridge ── spawn python gyoshu_bridge.py ──────►    ├─ bridge.sock       (unix, umask 0177)
  6 sendSocketRequest JSON-RPC 2.0, newline-delimited        └─ bridge.port       (win32 TCP fallback)
  7 finally lock.release()
```

**Paths** (src/tools/python-repl/paths.ts): runtime dir priority is `$XDG_RUNTIME_DIR/omc` (only if the dir is absolute, non-symlink, owned by uid, mode `0700` — `isSecureRuntimeDir`, paths.ts:51-63), else `~/Library/Caches/omc/runtime` (macOS) / `/tmp/omc/runtime` (Linux) / `%LOCALAPPDATA%\omc\runtime` (Windows) / `os.tmpdir()`. Session IDs are *always* SHA-256-hashed to 12 hex chars before path use (paths.ts:125-133, "SECURITY: Always hash — prevents traversal via short IDs like `..`"), keeping socket paths under the ~104-byte AF_UNIX limit. `validatePathSegment` additionally rejects `..`, separators, NUL, >255 bytes, Windows reserved device names (`CON`,`NUL`,`COM1`…), and trailing dot/space (paths.ts:205-246).

**Session lock** (session-lock.ts): file-based single-writer per session. `tryAcquire` = read existing lock → break if stale → `open(O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o644)` → write `LockInfo` `{lockId: uuid, pid, processStartTime, hostname, acquiredAt}` → fsync → *re-read and compare lockId* to detect overwrite races (session-lock.ts:377-450). Staleness: age > `STALE_LOCK_AGE_MS` 60 s AND holder dead-or-PID-reused; locks from a *different hostname* need age > 5 min (`REMOTE_LOCK_STALE_AGE_MS`, session-lock.ts:295-312). Retry every 100 ms until `queueTimeout`, then `LockTimeoutError` is formatted as a "Session Busy" report naming the holder PID/host/since (tool.ts:286-310). PID-reuse detection compares `getProcessStartTime(pid)` against the recorded value, fail-closed on Linux/macOS (session-lock.ts:107-165).

**Bridge lifecycle** (bridge-manager.ts): `ensureBridge` reads `bridge_meta.json` (`BridgeMeta = {pid, socketPath, startedAt, sessionId, pythonEnv, processStartTime?}`, types.ts:4-11) and re-validates four ways before reuse — sessionId match (anti-poisoning), socketPath equals the canonical path (anti-hijack; skipped for `tcp:<port>` meta), process identity (alive + start-time match, fail-closed; bridge-manager.ts:197-219), and the socket file is actually `S_ISSOCK` — otherwise SIGKILL the orphan and respawn (bridge-manager.ts:524-570). Spawn: `spawn(venvPython, [gyoshu_bridge.py, socketPath], {detached: true, env: {PYTHONUNBUFFERED:'1', OMC_PARENT_PID: String(process.pid), OMC_PYTHON_SANDBOX?...}})`, unref'd, stderr captured with a 64 KB cap; polls every 100 ms up to `BRIDGE_SPAWN_TIMEOUT_MS` 30 s for the socket (or `bridge.port` on Windows), short-circuiting if the child exits first and deleting any non-socket file left at the path ("poisoning attempt", bridge-manager.ts:433-471). Python env: requires `<projectDir>/.venv/{bin|Scripts}/python`, falls back to system `python3`, else errors with venv-creation instructions (bridge-manager.ts:146-182). Script path override: `OMC_BRIDGE_SCRIPT` (must basename `gyoshu_bridge.py`).

**Teardown**: `killBridgeWithEscalation` = SIGINT → wait 5000 ms → SIGTERM → wait 2500 ms → SIGKILL → wait 1000 ms, each stage killing the *process group* (`process.kill(-pid, sig)`; `taskkill /T [/F]` on Windows) and re-verifying identity between polls (bridge-manager.ts:590-669). `interrupt` first tries a graceful JSON-RPC `interrupt` (5 s), then escalates. `reset` that fails its RPC also escalates and reports "Bridge Restarted". Sweepers: `cleanupOwnedBridgeSessions()` (only sessions this process spawned, tracked in an in-memory Set) and `cleanupStaleBridges()` (scan whole runtime dir; anything with invalid meta or dead/reused PID gets its meta/socket/port/lock files removed; exported but not currently called from any non-test src site).

**Transport** (socket-client.ts): JSON-RPC 2.0, one request per connection, newline-delimited; request id is a UUID and the response id must match; 2 MB response cap; default timeout 60 s (execute uses `executionTimeout + 10000`). `socketPath` beginning `tcp:` connects to `127.0.0.1:<port>` (Windows AF_UNIX fallback). On `SocketConnectionError` during execute, the handler respawns the bridge once and retries (tool.ts:616-634). A `SocketTimeoutError` is *not* fatal: the reply says "The execution is still running in the background. Use the interrupt action to stop it." (tool.ts:382-394).

**Python side** (`bridge/gyoshu_bridge.py`, 1171 lines, shipped verbatim — the one non-TS runtime component): AF_UNIX (bind under `umask 0o177` with post-bind owner/mode verification) or TCP-localhost fallback that writes `bridge.port` and rejects non-127.0.0.1 peers; 10 MB request-line cap; SIGALRM-based execution timeout; 1 MB `BoundedStringIO` stdout/stderr caps; RSS/VMS memory reporting; parent watchdog thread that shuts down when `os.getppid()` no longer equals `OMC_PARENT_PID` (poll interval `OMC_PARENT_POLL_INTERVAL_MS`, default 1000 ms, floor 250 ms) — so `detached:true` exists for group-kill semantics, not for outliving the MCP server.

**Sandbox (unconditional)**: despite the `pythonSandbox` security flag, the bridge comment at line 545 states "Always restrict JSON-RPC supplied execution; OMC_PYTHON_SANDBOX no longer gates builtin safety." User code runs against an allowlisted `__builtins__` (`SANDBOX_BLOCKED_BUILTINS` removes `__import__ breakpoint compile delattr dir eval exec getattr globals help input locals open setattr type vars`), `__import__` is replaced by a hook raising ImportError, and a pre-exec AST walk (`validate_user_code_ast`) rejects any `import`/`from-import`, any dunder attribute access, `format`/`format_map` calls, and any Name matching a blocked builtin. Consequence: the tool description's promise of "pandas, numpy, matplotlib" (tool.ts:686) and the venv error hint `pip install pandas numpy matplotlib` (tool.ts:599, bridge-manager.ts:180) are unreachable in the current build — no import can execute. Only whitelisted builtins plus injected `clean_memory`/`get_memory` helpers (wrapped in `_SafeBridgeHelper` so their function globals are not reachable) are available.

**Structured markers**: stdout lines matching `^\s*\[([A-Z][A-Z0-9_-]*)(?::([^\]]+))?\]\s*(.*)$` are parsed into `{type, subtype, content, line_number, category, valid}` against a fixed taxonomy — research_process (`OBJECTIVE HYPOTHESIS EXPERIMENT OBSERVATION ANALYSIS CONCLUSION`), data_operations (`DATA SHAPE DTYPE RANGE MISSING MEMORY`), calculations (`CALC METRIC STAT CORR`), artifacts (`PLOT ARTIFACT TABLE FIGURE`), insights (`FINDING INSIGHT PATTERN`), workflow (`STEP STAGE CHECKPOINT CHECK INFO WARNING ERROR DEBUG`), scientific (`CITATION LIMITATION NEXT_STEP DECISION`) (gyoshu_bridge.py:106-154). The TS-side `ExecuteResult.artifacts` field (types.ts:31) is never populated by the bridge — vestigial. The `scientist` agent (agents/scientist.md) hard-mandates python_repl over Bash heredocs, which is this tool's primary consumer.

## lsp_* — Language Server Protocol suite

Twelve tools (lsp-tools.ts:493-506): `lsp_hover`, `lsp_goto_definition`, `lsp_find_references`, `lsp_document_symbols`, `lsp_workspace_symbols`, `lsp_diagnostics`, `lsp_diagnostics_directory`, `lsp_servers`, `lsp_prepare_rename`, `lsp_rename`, `lsp_code_actions`, `lsp_code_action_resolve`. Positional inputs are 1-indexed lines / 0-indexed characters, converted to LSP 0-indexed internally. `lsp_rename` is deliberately read-only: it returns the WorkspaceEdit as a diff-like listing with "Note: Use the Edit tool to apply these changes." (lsp-tools.ts:350). `lsp_code_action_resolve` re-runs `codeActions` and picks by 1-indexed `actionIndex` rather than resolving via `codeAction/resolve`.

**Server registry** (lsp/servers.ts:25-167): 20 hardcoded `LspServerConfig` entries `{name, command, args, extensions, installHint, initializationOptions?, initializeTimeoutMs?}` — typescript-language-server, `ty server` (Python — astral's ty, not pyright), rust-analyzer, gopls, clangd, jdtls, vscode-json/html/css-language-server, vue-language-server, yaml-language-server, intelephense, solargraph, lua-language-server, `kotlin-lsp` (initializeTimeoutMs `5*60*1000`), elixir-ls, omnisharp, `dart language-server --protocol=lsp`, sourcekit-lsp, verible-verilog-ls. Selection is by file extension only (`getServerForFile`); availability via `which`/`where` probe (`commandExists`). `lsp_servers` prints Installed vs Not Installed with install hints.

**Client** (lsp/client.ts, 1132 lines): spawns the server over stdio, speaks `Content-Length`-framed JSON-RPC 2.0 with a hand-rolled buffer parser (50 MB `MAX_BUFFER_SIZE`, overflow resets buffer and rejects all pending requests). Request timeout `OMC_LSP_TIMEOUT_MS` (default `15_000`), raised to the server's `initializeTimeoutMs` for `initialize` only. Initialize advertises hover markdown, hierarchical documentSymbol, prepareRename, publishDiagnostics tagSupport; records `capabilities.diagnosticProvider` as `supportsPullDiagnostics`. `lsp_diagnostics` prefers LSP 3.17 pull (`textDocument/diagnostic`), else opens the doc and `waitForDiagnostics(file, 30_000)` — a notification-driven waiter with per-URI resolver lists replacing fixed sleeps (client.ts:680-709). `openDocument` reads the file, sends `didOpen`, then sleeps 100 ms. On Windows, spawn uses `shell: true` because npm shims are `.cmd` (#569; safe since commands come from the hardcoded registry).

**Pooling and eviction** (`LspClientManager`, client.ts:819-1112): pool key `` `${workspaceRoot}:${serverConfig.command}:${containerId ?? 'host'}` ``; workspace root found by walking up for markers `build.gradle(.kts) settings.gradle(.kts) pom.xml package.json tsconfig.json pyproject.toml Cargo.toml go.mod .git`. Idle eviction after `OMC_LSP_IDLE_TIMEOUT_MS` (default 5 min) via per-key unref'd deadline timers plus a 60 s sweep (`OMC_LSP_IDLE_CHECK_INTERVAL_MS`); every tool call runs inside `runWithClientLease` which increments an in-flight counter so a client is never evicted mid-request (lsp-tools.ts:36-83, client.ts:903-940). Process `exit`/SIGTERM/SIGINT/SIGHUP handlers `forceKill()` (SIGKILL) every pooled server to prevent orphans. The manager is a `globalThis.__omcLspClientManager` singleton to survive double module loading.

**Devcontainer transparency** (lsp/devcontainer.ts): if the workspace has a `devcontainer.json` (`.devcontainer/devcontainer.json`, `.devcontainer.json`, or `.devcontainer/*/devcontainer.json`) and a matching running container is found via `docker ps -q` + `docker inspect` label scoring (`devcontainer.local_folder`/`vsch.local.folder` +4, `devcontainer.config_file`/`vsch.config.file` +3, mount-derived root +1), the server is spawned as `docker exec -i -w <containerWorkspaceRoot> <containerId> <command> <args...>` and *all* URIs are rewritten host↔container in both directions, including nested `changes` maps in WorkspaceEdits (client.ts:762-807). Override: `OMC_LSP_CONTAINER_ID`. No Docker → silently null → host spawn (fail-open).

**Directory diagnostics** (`lsp_diagnostics_directory` → src/tools/diagnostics/): strategy `tsc | lsp | auto` (auto = tsc iff `tsconfig.json` exists). tsc path runs `tsc --noEmit --pretty false` via execFileSync and regex-parses `file(line,col): error TS1234: message` (tsc-runner.ts:45-93). LSP fallback walks `.ts/.tsx/.js/.jsx` (skipping `node_modules dist build .git`), opens each file under a lease, waits only `LSP_DIAGNOSTICS_WAIT_MS = 300` ms per file, and aggregates; missing-server errors are pattern-matched (regex pinned to the throw in client.ts:186) into deduplicated `installHints`, and `success` is false when every file was skipped (lsp-aggregator.ts:78-149).

## ast_grep_* — structural search and rewrite

`ast_grep_search` and `ast_grep_replace` (ast-tools.ts:285-652) wrap `@ast-grep/napi` with meta-variable patterns (`$NAME`, `$$$ARGS`). 17 languages (`SUPPORTED_LANGUAGES`, ast-tools.ts:133-151) mapped from 29 extensions; file discovery is a manual walk skipping `node_modules .git dist build __pycache__ .venv venv`, capped at 1000 files. Search: `context` 0-10 (default 2) lines, `maxResults` 1-100 (default 20), output as `> `-prefixed numbered context blocks. Replace: **`dryRun` defaults to `true`**; edits are collected per file, sorted by offset descending and applied end-to-start so offsets stay valid; meta-variables in the replacement are substituted from `match.getMatch(varName)` with `$` escaped as `$$$$` to defuse JS replaceAll patterns (ast-tools.ts:544-557); display capped at 50 changes.

**Native-module degradation**: `@ast-grep/napi` is resolved lazily via `createRequire()` (CJS resolution honors `NODE_PATH`; ESM `import()` does not) with a dynamic-import fallback; the esbuild bundle's banner prepends `npm root -g` to `NODE_PATH` and calls `Module._initPaths()` at startup (scripts/build-mcp-server.mjs:18-30; same logic in `bridge/run-mcp-server.sh`). The tools are *always registered*; if the module is missing they return "Install it with: npm install -g @ast-grep/napi" plus the captured load error rather than failing ListTools (tool-registry.ts:8-10, ast-tools.ts:29-50).

**Path guard**: `validateToolPath` confines `path` to the *literal git toplevel* (not the superproject — a submodule stays confined to itself, #3349/PR #3350) only when `security.restrictToolPaths` is on; sources are `.claude/omc.jsonc` / `~/.config/claude-omc/config.jsonc` `security` section or the master switch `OMC_SECURITY=strict` (defaults all-off; src/lib/security-config.ts). The code comment "Only enforced when OMC_RESTRICT_TOOL_PATHS=true" (ast-tools.ts:54) references an env var that no longer exists — stale doc; the error text names the real knobs.

## deepinit_manifest — incremental /deepinit change detection

Deterministic manifest diffing so the `deepinit` skill regenerates AGENTS.md only for structurally changed directories (issue #1719). Actions `diff | save | check`; `mode: incremental|full` (diff only), `dryRun` (save only), with explicit cross-action parameter rejection (deepinit-manifest.ts:422-433). `workingDirectory` is validated by `validateWorkingDirectory` (must be inside the git toplevel/cwd trust boundary, worktree-paths.ts:1162). Manifest lives at `<omcRoot>/deepinit-manifest.json` — `getOmcRoot` is `OMC_STATE_DIR`/workspace-marker/git aware, so normally `.omc/deepinit-manifest.json` — written via `atomicWriteJsonSync`. Schema: `{version: 1, generatedAt, directories: {<relPath>: {files: string[] sorted}}}`.

Scanner (deepinit-manifest.ts:126-200): recursive walk with `MAX_DEPTH` 50 and `MAX_DIRECTORIES` 10 000, excluding all dotdirs plus `node_modules dist build __pycache__ coverage .next .nuxt`; symlinks are skipped entirely, directories are realpath-checked to remain under the project root, and inode tracking breaks symlink loops; only directories *containing files* are recorded; keys use `/` separators (`.` = root). Diff (`computeDiff`, :233-320) marks `added/deleted/modified/unchanged` with human-readable reasons ("files added: x, y"), then applies **ancestor cascading**: any added/deleted directory flips every `unchanged` ancestor (and `.`) to `modified` so parent AGENTS.md "Subdirectories" tables get refreshed. Output is raw JSON with a summary count block. Compares file *lists*, not contents — content changes alone never mark a directory changed (stated in the action description, :86).

## list/load_omc_skills — learned-skill discovery

Three read-only tools (skills-tools.ts): `load_omc_skills_local` (project scope), `load_omc_skills_global` (user scope, zero-arg), `list_omc_skills` (both; "Project skills take priority over user skills with the same ID"). They delegate to the learner subsystem's `loadAllSkills` (src/hooks/learner/loader.ts:26-69): search dirs are project `.omc/skills/` and `.agents/skills/` (constants.ts:17-20) and user `~/.omc/skills/` plus `$CLAUDE_CONFIG_DIR|~/.claude/skills/omc-learned/`; dedupe by realpath with symlink-escape boundary checks; project priority 1 beats user 0 on ID collision. Output is markdown metadata (id, name, description, triggers, tags, scope, relative path) — the tools list skills, they do not inject skill *content*. Guards: `projectRoot` max 500 chars, raw `..` rejected, resolved path must sit under cwd or `$HOME` (skills-tools.ts:26-42); a `_sanitizeSkillContent` helper (truncate to `MAX_SKILL_CONTENT_LENGTH` 4000, strip `<system|human|assistant|user|tool_use|tool_result>` role-boundary lines) exists for content injection but is currently unused by these three tools (underscore-prefixed).

## Patterns for sibling harnesses

- **Single registry module, thin server shell**: keep the tool table (`allTools` + env filtering + zod→JSON-schema) in a side-effect-free module so tests exercise the exact ListTools/CallTool path without starting a transport (tool-registry.ts). Adopt for any omx/omd MCP surface.
- **Category tagging + one kill-switch env var**: tag every tool with a category at aggregation time and honor a comma-separated `<HARNESS>_DISABLE_TOOLS` with aliases and silent-ignore semantics — cheap, safe degradation lever.
- **Hash-then-join session namespacing**: never place caller-supplied IDs in paths; SHA-256-truncate (12 hex) both for traversal safety and unix-socket length limits, and keep a separate strict `validatePathSegment` for human-visible IDs.
- **Sidecar process trust chain**: metadata file + four-step revalidation (owner ID match, canonical path match, PID+start-time identity fail-closed, socket-type check) before reusing any long-lived helper process; respawn on any mismatch. Directly reusable for omx background eval workers.
- **Signal escalation ladder with group kill**: SIGINT 5 s → SIGTERM 2.5 s → SIGKILL 1 s against `-pid` (or `taskkill /T`), re-verifying identity between stages — one function, reused by interrupt, reset, and session-end.
- **Parent watchdog in the child**: pass `PARENT_PID` in env and have the sidecar poll `getppid()`; combined with `detached:true` this gives clean group-kill *and* no orphans when the parent dies uncleanly.
- **O_EXCL + verify-after-write file lock**: exclusive-create JSON lock with uuid, fsync, then re-read to confirm ownership; stale-break only when age>60 s AND holder provably dead; longer threshold for foreign hostnames. A simpler, portable alternative to flock for cross-process gating.
- **Lease-protected resource pool**: wrap every use in `runWithLease` that bumps an in-flight counter so idle eviction can never reap a busy client; unref all timers so the pool never keeps the process alive.
- **Always-register, degrade-at-call for native deps**: keep tools in ListTools even when their native module is missing and return an install hint at call time; resolve via `createRequire` + NODE_PATH banner so a bundled CJS can find globally installed addons.
- **Manifest-diff for incremental doc generation**: persist sorted per-directory file lists and cascade `modified` up ancestors on add/delete — makes any "regenerate docs for changed dirs only" feature deterministic (fits omp-organize / omd rebuilds).
- **Structured stdout markers**: a `[TYPE:subtype] content` line grammar with a fixed category taxonomy turns free-form script output into machine-parseable findings; omx evaluator scripts could emit the same grammar.
- **Fail-open detection, fail-closed identity**: environment probing (devcontainer, venv, server binaries) degrades silently to a working default, but anything security-relevant (PID reuse, lock ownership, socket type) errs toward "assume compromised, rebuild".
