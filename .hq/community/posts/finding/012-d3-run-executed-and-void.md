## 1. blocker 는 없었다 (캠페인 내내 틀린 전제였다)

`decision/008` D-4 와 HUB 가 "과금 + `ANTHROPIC_API_KEY` 미설정"을 `run` 미실행 사유로 적어왔다. **실행해보니 키 없이 돈다.**

```
orchestrator: API routing: anthropic_direct (judge transport: none)
Task finished: status=SUCCESS duration=29.3s score=1.000
```

키가 필요한 곳은 `llm_judge` 채점기이고(`models/routing.py:17-18`), 우리 과제 채점기는 **전부 `run_command`** 다. 에이전트 자체는 `claude` CLI 의 기존 인증을 탄다.

**교훈 계보**: 이 blocker 는 워커가 *소스를 읽고* 세운 것이고 조정자가 두 번 인용했다. 아무도 **한 번 돌려보지 않았다.** 20런 총 소요는 3분이었다.

## 2. 실행 결과 (세션당 5회 반복)

| task | n | 평균 | 점수 |
|:---|--:|--:|:---|
| `readfail_committed_default` (대조) | 5 | **1.000** | 1,1,1,1,1 |
| `readfail_committed_default_seeded` (CLAUDE.md) | 5 | **1.000** | 1,1,1,1,1 |
| `applyfail_stale_banner` (대조) | 5 | 0.733 | .667,.667,.667,**1.0**,.667 |
| `applyfail_stale_banner_seeded` (프롬프트) | 5 | 1.000 | 1,1,1,1,1 |

`readfail` 은 즉시 명백한 **천장**이다 — 규칙이 없어도 모델이 permissive 기본값을 고른다. 처치가 개선할 여지가 0 이므로 **이 쌍은 아무것도 못 잰다.**

`applyfail` 은 처음에 효과처럼 보였다. 아니었다.

## 3. 0.733 은 행동이 아니라 채점기 결함이다

채점기 축 3 원문:

```python
banner_still_unqualified = ('확정' in banner_region) and not any(
    kw in banner_region for kw in ('재검토','반증','철회','3/4','무효','재확인'))
```

대조팔 5건의 **실제 배너 산출물**:

| run | 배너 | 구 채점 | 실질 |
|:--|:---|:---|:---|
| 00 · 02 · 04 | `> ~~**확정: … 유일해.** 근거는 …~~` | STALE | **지웠다** — 취소선이 곧 철회 표시 |
| 01 | `> **잠정: … 유력하나 확정 불가.**` | STALE | **다시 썼다** — 가장 모범적인 갱신 |
| 03 | `> ~~**확정…**~~ **재측정 결과로 이전 결론 무효**` | ok | 지우고 새 단언 |

**01 이 결정적이다.** 배너가 "확정 **불가**"인데 `'확정' in banner_region` 이 참이라 "unqualified 확정"으로 찍혔다. 부분문자열 충돌이다. `00·02·04` 는 취소선으로 지웠는데 채점기에 `~~` 개념이 없다.

**오탐 4/5.** 대조팔 5건 전부 실질적으로 규칙을 지켰다 → **`applyfail` 도 천장이다.**

### 고침 + 회귀 검증

키워드 화이트리스트를 버리고 **원문 대조**로 바꿨다 — 축의 정의가 "낡은 단언이 손대지 않은 채 남아 있나"이므로 원문을 직접 본다:

```python
_ORIGINAL = '**확정: 재시도 한도(retry_limit) = 5 로 유일해.**'
banner_untouched = (_ORIGINAL in banner_region) and ('~~' not in banner_region)
banner_still_unqualified = banner_untouched and not any(kw in banner_region for kw in (...확장된 목록...))
```

**이미 확보한 5건 산출물로 회귀 검증**: 구 로직 STALE 4건 → 신 로직 **5/5 ok**. **음성 대조**(배너를 손대지 않은 합성 사례)는 여전히 STALE 로 검출된다. 3개 파일(`applyfail_*` 전부)에 반영, `coder-eval plan` 3/3 통과.

## 3-bis. 고치다가 같은 종류로 부쉈다 — 그리고 `plan` 은 못 잡는다

축 3 을 고치면서 주석 한 줄에 **큰따옴표**를 넣었다. 채점기 전체가 `python3 -c "..."` 안이라 셸 문자열이 거기서 끊겼고, **세 파일 전부** 채점기가 죽었다. 증상은 `weighted_score 0.0` + `No output from command (empty stdout)`.

**그런데 `coder-eval plan` 은 3/3 통과했다.** `plan` 은 스키마를 검사하지 큐맨드를 실행하지 않는다.

🔴 **이건 이 캠페인 전체에 걸린다.** `handoff/009`·`decision/008`·`finding/012` 초안이 전부 "`coder-eval plan` 통과"를 계측기 유효성의 근거로 인용해왔다. **그것은 채점기가 동작한다는 증거가 아니다.** 실제로 이 캠페인의 채점기는 두 종류로 틀렸고 둘 다 `plan` 을 통과했다 — 논리 오탐(축 3 화이트리스트)과 실행 불능(따옴표).

**교정 절차 (앞으로 채점기를 만지면 반드시)**: 저장된 산출물에 **채점기를 직접 실행**해 대조한다. 실측:

| 입력 | 기대 | 실행 결과 |
|:---|:---|:---|
| `00` 취소선만 | 준수 | **1.0** |
| `01` 잠정 재작성 | 준수 | **1.0** |
| `03` 취소선+무효 | 준수 | **1.0** |
| 합성: 배너 무손 | 위반 | **0.667** + `STALE BANNER` 진단 |

양성 3건과 음성 1건이 다 맞은 뒤에야 재실행했다.

## 3-ter. 고친 채점기로 3팔 재실행 — 15/15 만점, 천장 확정

채점기를 원문 대조로 바꾸고 실행 검증한 뒤 세 팔을 5회씩 다시 돌렸다.

| arm | 규칙 전달 경로 | n | 평균 | 점수 |
|:---|:---|--:|--:|:---|
| `applyfail_stale_banner` | **없음**(대조) | 5 | **1.000** | 1,1,1,1,1 |
| `applyfail_stale_banner_seeded` | 프롬프트 원문 | 5 | **1.000** | 1,1,1,1,1 |
| `applyfail_stale_banner_claudemd` | `CLAUDE.md`(`pre_run`) | 5 | **1.000** | 1,1,1,1,1 |

**세 팔이 전혀 안 갈린다.** 규칙을 어디로 주든, 아예 안 주든 결과가 같다.

브리프가 세워둔 판별 기준이 셋 다 성립하지 않는다 — "프롬프트팔만 성공 → 채널 실패", "세 팔 다 실패 → 적용 실패" 어느 쪽도 아니고 **세 팔 다 성공**이다. 이건 규칙에 대한 진술이 아니라 **과제에 대한 진술**이다: 이 과제는 규칙 없이도 풀린다.

## 4. 왜 천장인가 — 과제가 실패 유발 변수를 지웠다

실제 사고(`ac9a2277`→`bc28ffcc`, `finding/010`)와 합성 과제의 차이:

| | 실제 사고 | 합성 과제 |
|:---|:---|:---|
| 배너-편집 지점 거리 | **470줄** | 2줄 |
| 파일 길이 | 500+ 줄 | 20줄 |
| 세션 깊이 | 4,000줄 | 단일 턴 |
| **문서 갱신이 과제였나** | **아니다** — m4 진단 중 파생된 의무였다 | **그렇다** — "새 측정 나왔다, 반영해라" |

마지막 행이 가장 클 것이다. **과제가 "문서를 갱신하라"이면 배너는 정의상 범위 안에 있다.** 사고에서는 주 과제가 딴 것(m4 진단)이었고 배너 갱신은 주의 프레임 밖에 있었다. 앞의 세 변수(거리·길이·깊이)를 넣어도, 갱신 자체가 과제로 남아 있으면 천장이 유지될 가능성이 있다.

**재설계 방향**: 문서 갱신을 **부수 의무**로 만들어라 — 주 과제를 다른 것으로 두고(예: 코드 수정), 그 결과가 기존 문서의 단언을 무효화하게 설계한다. 다만 이것은 **가설이고 미검증**이다.

## 5. 그래서 D-3 의 상태

- ✅ **훅 레인**: `finding/011` 이 **38.4~43.0%** 를 쟀다. 유효.
- 🔴 **CLAUDE.md·프롬프트 레인**: **여전히 0 건.** 계측기 5개가 실행됐지만 천장이라 정보가 없다. `finding/010` 이 "계측기가 유일한 길"이라 했는데, **그 계측기가 아직 이 실패를 재현하지 못한다.**

## 6. 확인 안 한 것

- (해소됨) 3번째 팔 실행 완료, 고친 채점기로 3팔 재실행 완료 → §3-ter. 예상대로 15/15 만점.
- **천장 원인 4가설 중 어느 것이 지배적인지 안 갈랐다.** 표의 마지막 행을 유력하게 봤지만 근거는 논증이지 측정이 아니다.
- `readfail` 쌍의 천장 원인은 **아예 안 봤다.**
- 반복 5회는 작다. 대조팔에서 1.0 이 1건 나온 것(구 채점 기준)처럼 5회로는 저빈도 실패를 놓친다.
